<section id="dita" class="reveal">

  <div class="section-label">Content architecture</div>

  <h2 class="section-title">DITA — the backbone of<br><em style="font-style:italic; color: var(--teal);">reusable content</em></h2>

  <p class="section-sub">Every topic is typed. Every shared phrase is referenced, not copied. Every product variant is a filter — not a separate file.</p>


  <div class="features-grid">

    <div class="feature-cell">

      <div class="feature-icon" style="background: var(--teal-light);">📐</div>

      <h3 class="feature-title">Typed topics</h3>

      <p class="feature-desc">Every page is a Concept, Task, or Reference. Writers can't accidentally mix a how-to with a reference table. Structure is enforced by the XML schema itself.</p>

      <span class="feature-tag">concept · task · reference</span>

    </div>

    <div class="feature-cell">

      <div class="feature-icon" style="background: var(--rust-light);">🔁</div>

      <h3 class="feature-title">Conrefs</h3>

      <p class="feature-desc">Write a safety warning once. Reference it in 200 topics. One edit propagates everywhere automatically at build time. Zero drift, zero duplication.</p>

      <span class="feature-tag">conref · content reuse</span>

    </div>

    <div class="feature-cell">

      <div class="feature-icon" style="background: var(--gold-light);">🗝</div>

      <h3 class="feature-title">Key definitions</h3>

      <p class="feature-desc">Product names, URLs, version numbers defined in one keydef file. White-label customers override specific keys at build time — no find-and-replace.</p>

      <span class="feature-tag">keyref · keydef · variables</span>

    </div>

    <div class="feature-cell">

      <div class="feature-icon" style="background: var(--teal-light);">🎯</div>

      <h3 class="feature-title">Conditional filtering</h3>

      <p class="feature-desc">Tag any block with <code style="font-size:12px;background:var(--cream);padding:1px 5px;border-radius:3px;">product="A B"</code> or <code style="font-size:12px;background:var(--cream);padding:1px 5px;border-radius:3px;">audience="enterprise"</code>. DITAVAL files select what appears in each customer's build. Same source, different outputs.</p>

      <span class="feature-tag">DITAVAL · @product · @audience</span>

    </div>

    <div class="feature-cell">

      <div class="feature-icon" style="background: var(--rust-light);">🗺</div>

      <h3 class="feature-title">Map hierarchy</h3>

      <p class="feature-desc">The .ditamap is your TOC as code. It defines hierarchy, topic order, and cross-references. No more ad-hoc naming in Confluence — structure lives in the repo.</p>

      <span class="feature-tag">ditamap · topichead · topicref</span>

    </div>

    <div class="feature-cell">

      <div class="feature-icon" style="background: var(--gold-light);">🔗</div>

      <h3 class="feature-title">Relationship tables</h3>

      <p class="feature-desc">Define cross-topic relationships in the map, not inside topics. Keeps content modular and portable. Links are generated at build time, not hardcoded in XML.</p>

      <span class="feature-tag">reltable · related-links</span>

    </div>

  </div>
